# Tapas.io 웹 자동화 프로젝트

이 프로젝트는 웹툰 플랫폼인 **Tapas.io**에서 사용자가 작품을 검색하고, 에피소드를 선택해 이동하는 **핵심 동작들을 자동으로 테스트**하도록 만든 포트폴리오입니다.

## 💡 왜 이렇게 만들었나요?
단순히 테스트 코드를 짜는 것에 그치지 않고, **"나중에 웹사이트 화면이 조금 바뀌어도 테스트가 쉽게 고장 나지 않게"** 만드는 데 가장 큰 신경을 썼습니다.

### 핵심 포인트
1. **유지보수가 쉬운 구조 (POM 패턴)**: 화면 단위로 기능을 쪼개서 파일로 만들었습니다. 나중에 화면 구성이 바뀌어도 해당 파일만 수정하면 되도록 만들었습니다.
2. **데이터 따로 관리**: 검색어 같은 테스트용 데이터를 코드 안에 직접 넣지 않고 따로 파일로 분리했습니다. 데이터만 바꾸면 테스트도 바로 수정됩니다.
3. **환경 설정**: 테스트할 사이트 주소 등을 코드 밖에서 설정할 수 있게 해서, 나중에 다른 사이트 테스트할 때도 코드를 다 뜯어고칠 필요가 없게 했습니다.

---

## 🚀 테스트 기능 리스트

| 기능 | 설명 |
| :--- | :--- |
| **작품 검색** | 검색창에 원하는 작품명을 입력하고, 검색 결과에서 작품을 잘 찾는지 확인합니다. |
| **에피소드 선택** | 작품 상세 페이지에서 에피소드 목록 중 하나를 잘 선택해 들어가는지 확인합니다. |
| **내비게이션** | 에피소드 안에서 '이전 화', '다음 화' 버튼을 눌러 잘 이동하는지 확인합니다. |

---

## 🛠 기술적 설계 철학

### 1. 안정적인 테스트 만들기
화면이 바뀔 때마다 테스트가 실패하면 진짜 골치 아프죠. 그래서 **눈에 보이는 텍스트(예: "Next")**나 **개발자가 기능 구현을 위해 미리 심어둔 클래스명(.js-next-ep-btn)**을 이용해 요소를 찾도록 했습니다. 이렇게 하면 사이트 디자인이 바뀌어도 테스트는 잘 깨지지 않습니다.

### 2. 효율적인 테스트
로그인 기능은 보안(캡챠) 문제로 자동화가 어려웠습니다. 그래서 **로그인 없이도 수행할 수 있는 가장 중요한 사용자 흐름(작품 찾고 읽기)**에 집중하여 자동화 효율을 높였습니다.

## 📈 실행 방법
- **실행**: `npx playwright test`
- **리포트 확인**: 테스트 실패 시 영상과 함께 리포트가 자동으로 생성됩니다.
