# Tapas.io QA Automation Showcase

이 프로젝트는 웹툰 플랫폼 **Tapas.io**의 핵심 사용자 흐름을 자동화하여, 효율적인 테스트 품질을 확보하기 위해 구축된 **QA 자동화 포트폴리오**입니다.

## 💡 프로젝트 기획 의도
단순한 코드 자동화가 아닌, **"유지보수가 쉽고, 환경 변화에 강하며, 비즈니스 가치가 높은"** 테스트 자동화 환경을 구축하는 것에 중점을 두었습니다.

### 핵심 해결 과제
1. **유지보수성**: UI 변경 시 테스트가 깨지지 않도록 기능 기반 로케이터 전략을 적용했습니다.
2. **확장성**: Page Object Model(POM)을 통해 페이지 구조가 변경되어도 테스트 코드는 최소한으로 수정하도록 설계했습니다.
3. **환경 대응**: `.env`를 도입하여 운영/개발 환경에 상관없이 테스트 환경 전환이 가능하도록 했습니다.

## 🚀 주요 테스트 케이스 리스트

| 시나리오 | 검증 목표 | 가치 (Value) |
| :--- | :--- | :--- |
| **작품 검색 및 탐색** | 검색 기능 및 작품 상세 진입 확인 | 서비스의 핵심 진입점 품질 확보 |
| **에피소드 목록 선택** | 에피소드 목록에서 특정 에피소드로 이동 | 콘텐츠 소비 시작점 검증 |
| **양방향 내비게이션** | 에피소드 뷰어 내 이전/다음 이동 버튼 동작 | 사용자의 콘텐츠 연속 소비 흐름 보장 |

## 🛠 기술적 설계 철학

### 1. 왜 이런 구조인가요? (Architecture)
- **Page Object Model (POM)**: 각 페이지의 구조와 기능을 별도의 파일로 캡슐화했습니다. 화면 UI가 바뀌어도 테스트 로직을 수정할 필요가 없게 설계했습니다.
- **Data-Driven Approach**: 테스트에 필요한 검색어 등 데이터를 `data/` 파일로 분리하여 코드 수정 없이 데이터만 변경하여 다양한 시나리오를 테스트할 수 있습니다.
- **Robust Locators**: 동적 ID 대신, 기능 중심의 클래스(`.js-next-ep-btn` 등)를 사용하여 테스트 안정성을 극대화했습니다.

### 2. 기술적 핵심 전략 (Strategic Focus)
* **핵심 비즈니스 흐름 집중**: 자동화의 투자 대비 효율(ROI)을 고려하여, 실제 사용자가 가장 자주 이용하는 **탐색 및 에피소드 내비게이션 흐름**을 우선적으로 자동화하여 테스트 커버리지를 효율적으로 확보했습니다.
